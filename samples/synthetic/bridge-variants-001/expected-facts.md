# 四种受控变体：预期事实清单

版本：**1.0**；固定日期：2026-10-11（Asia/Shanghai）。状态：按用户认可的变体方案，由 agent 在制作变体 PDF 前固定。本轮只固定清单，四份 PDF 尚未生成，解析、模型调用和验收尚未运行；不能把清单当作能力验证结果。

机器预期以 [expectations.json](expectations.json) 为主要维护位置，本文解释修改点和判定方式；两者出现差异时修订并重新固定版本，不能静默改真值。[freeze.json](freeze.json) 保存清单摘要及本轮一致性检查。

## 1. 原件与共同边界

对照原件为 [bridge-demo-001.pdf](../bridge-demo-001/input/bridge-demo-001.pdf)，事实依据是先于原 PDF 制作固定的 [golden.json](../bridge-demo-001/golden.json)。用户已确认核心数量、面积、未知日期及否定分流，见 [确认记录](../../../experiments/business-extraction-001/results/baseline-approval.json)。变体预期由这些固定事实加上本次预定修改推导，不使用模型输出反向编写真值。

五份素材均采用下列边界：

- 两页、可选择文本、synthetic 明示；桥梁为溪桥演示桥 B-DEMO-001，两个构件为桥面铺装 C-DECK-01 和主梁 C-GIRDER-01。
- 保留原构件名称、类型和表 2 的描述范围。新增中部否定句仍属于主梁；表 2 的原描述范围不是主梁所有部位的穷举。
- 报告编制日期固定为 **2026-10-10**，不会随生成日期更新；所有观测日期未知。真实地址、机构、人员和专业评估仍不补造。
- 仅允许当前病害类型、面积指标和业务契约；不引入扫描、跨页表、合并单元格或新行业字段。
- 原件不重制；每份变体都独立从原件制作，不累计叠加其他变体的修改。字体、标题、表号、其余表格和未指定文字保持原件设计。
- 只有 PDF 是业务输入；清单、冻结记录和其他核验材料留在外围，不发送给抽取模型。未来制作程序使用独立创作配置，不导入本预期 JSON 作为生成数据，以便发现清单和 PDF 制作不一致。

### 3.1 missing-area：只缺 O-002 的面积数值

第 2 页正文替换为：

> 第三跨主梁左侧有 1 处露筋，面积未提供（单位 m²）。

表 4 中 D-002 / O-002 行的“面积”单元格由 `2.6 m²` 改为 `未提供（单位 m²）`，其编号、位置、处数以及其他行不变。该 PDF 的正文、表格、页眉页脚和说明均不得残留 `2.6`，避免模型从另一处找回旧数值。

明确保留单位，是为了单独检验缺少数值的处理。本例 O-002 必须为：

| 字段 | 预期 |
|---|---|
| area_original_value / area_value | 均为 null |
| area_original_unit / area_unit | 均为 m²，原单位有明确原文支持 |
| area_conversion | null，没有可换算的数值 |
| area_is_approximate | null，没有面积数值，不推定其精确性 |
| missing_fields | 恰含 observed_at、area_original_value、area_value、area_is_approximate，顺序不限 |
| acceptance_status / review_status | pending_review / unreviewed |

O-002 的病害、肯定性、单处范围、1 处数量、位置与对象关联保持不变；O-001/O-003 的面积和状态保持原件预期。九个业务记录中八个 accepted、一个 pending_review。拒绝整份素材、丢弃该处病害或观测、填 0/2.6 或借用 0.9 都不能通过。

### 3.2 additional-negative：新增一条主梁否定原文

在第 2 页两个肯定观测段落后、表 4 前插入：

> 第三跨主梁中部未见露筋。

它必须成为属于 C-GIRDER-01、位置为“第三跨主梁中部”的 negative statement。原有桥头否定句继续保留，三处肯定病害和全部面积不变；不增加新的病害编号、观测编号、处数或面积，不把中部否定句作为左侧/外侧肯定记录的支撑证据，也不推断整根主梁无露筋。

Statement 不具有正式 Observation 的日期/面积字段；清单不要求为否定陈述虚构这些业务属性。

### 3.3 duplicate-row：只增加一次同编号提及

第 1 页表 3 保持原列头，在原数据行后重复一次完整行：

| 病害编号 | 观测编号 | 位置 | 数量 | 面积 |
|---|---|---|---|---|
| D-001 | O-001 | 第三跨桥面 | 1 处 | 0.04 m² |

表 3 应有一行表头、两行相同的数据；正文不额外修改。仍只有一个 D-001 和一个 O-001，reported_count 仍为 1。不得把重复行当成第二次检测、把数量变成 2、把面积加为 0.08 或产生第四个病害/观测。完整解析须保留重复行；证据数量可以不同，不要求模型必须引用每次重复提及。

### 3.4 reordered-columns：只改变表 4 的列位置

表 4 列头由“病害编号 / 观测编号 / 位置 / 数量 / 面积”改为下表顺序，所有单元格随对应列移动；两条数据行的先后不变。第 1 页表 3 不变，不增加换单位、合并表头或跨页。

| 观测编号 | 面积 | 位置 | 病害编号 | 数量 |
|---|---|---|---|---|
| O-002 | 2.6 m² | 第三跨主梁左侧 | D-002 | 1 处 |
| O-003 | 0.9 m² | 第三跨主梁外侧边缘 | D-003 | 1 处 |

仍需正确匹配“左侧 → 2.6”“外侧边缘 → 0.9”，不能根据旧列位置读错值。表 4 的表题、构件关联、正文和所有业务事实保持原件预期。

## 4. 共用验收规则与后续执行约束

- 逐项检查机器清单列出的业务编号、字段、关联与接纳状态；不同 PDF 的 document_id、Defect/Observation 的程序 ID 可以不同，比较业务事实时使用原编号与所属构件。不得把同编号的不同 PDF 当作跨文档同一病害已被证明。
- 原始描述只允许在事实对照时归一 Unicode 空白；不能改数值、单位、否定或位置。Evidence 始终在该份新 PDF 的原始 Block.text 上匹配，不对清洗文本套用旧偏移。
- 页码是制作目标和后续待核验位置，现阶段不编造 block_id、bbox、charspan，不规定必须恰有 57 条证据。未来证据须与新解析快照一致，支持正确字段及关联，不能借用别行或否定句。
- 说明原文可保留为 unmapped，数量不固定；把使用说明当成真正病害统计、生成额外事实或错误范围结论，都需要作为失败记录。
- 制作验收先确认 PDF 的修改符合清单，随后分开检查 Docling、模型输出及程序校验。制作不符合清单时先修复素材，不用系统抽取结果改写预期来适应它。
- 后续拟采用当前成功实验的模型、Schema、系统提示词及参数，见 expectations.json 的 future_execution_baseline。每份独立调用两次，共十次；首次不带旧答案、诊断、golden 或修正反馈。输出缺失/被拒绝不能当作通过。
- 首次失败与后续修正成功分开保存。若需改提示词、Schema 或规则，明确记录新实验版本，整组重新跑；不能为某个失败样本单独放宽验收。两次成功只能支持该组受控条件，不足以估计长期准确率。

下一步需要先按这份清单制作四份变体 PDF，再分别进行 Docling 解析、独立 API 抽取和结果验收。本轮到固定预期清单为止。
