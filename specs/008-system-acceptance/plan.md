# S5.2 计划

## 顺序与隔离

1. T01 核对交接、Git、服务、配置（输出只含白名单非敏感字段）、保护文件摘要；不启动应用或触发生成。
2. T02 固定范围、持续场景/门槛、素材、独立预期；未定验收选择交由用户确认。用户已确认保留完整 PRD 门槛，并在标准/调用范围解释后授权继续执行；采用 [执行基线](execution.md)。
3. T03 准备专用图/卷/端口和 DATA_ROOT，复制既有 synthetic 发布文件；旧图仅读取。种子使用既有真实图/发布结果，事实值由独立预期判定；复制不是新真实抽取。新图不得使用旧卷。不得另启写旧 DATA_ROOT 的应用。
4. T04 执行本版本的组合验收：必要离线/真实图机制检查、新 TCP 持续场景、应用/图重启、模型/嵌入不可用降级、缺失产物错误。仅修改隔离副本，故障区分实际停服务、错误目的地址及注入替身；不停止共享 Ollama/旧图。旧阶段实验脚本不重跑。
5. T05 检查真实调用前的目的地、模型、载荷范围、trace 内容；仅按已确认次数执行新问答/角色样例。不得发送 golden、预期答案、专业资料或配置凭据；API key 只用于鉴权。
6. T06 启动/演示/限制文档、配置模板、依赖与约束脚本、素材指针核对；按 AC 编号评价，人工与真实素材缺口不计通过。
7. T07 文件/图保护与秘密精确扫描、本地链接核对、ADR 影响检查，任务和交接更新；只提交本轮授权文件，原 UI 修改单独保留，不 push。

交付核对发现 wheel 漏包 PDF.js `build/pdf.mjs` 和 `build/pdf.worker.mjs`（Git 的 build/ 忽略影响打包）。在 `pyproject.toml` 显式 force-include 既有 vendor/build，属于交付修复，不改变前端/业务。Git检查另发现这两个本机现有文件也未入旧提交，须强制归档其已验证原字节，与打包配置一同交付。首个wheel和失败检查保留，新构建另存目录；保护核对允许该一个构建配置计划内变更，uv.lock和所有src/旧证据仍须原字节保持。

## 新实验目录

阶段证据：`results/<run-id>/`，创建时要求不存在；运行数据/私有配置：`data/s52-<run-id>/`（Git 忽略）。保护摘要必须在任何新服务/写入前生成。进度结果逐次保存；首轮失败不覆盖；中断记录最后采样/进程/容器状态，不能写 passed。

故障验证细化、预期错误码/恢复时限/采样计划和独立请求在 [执行基线](execution.md)及机器基线先冻结。准备轮安装/包/HTTP检查不重跑。
