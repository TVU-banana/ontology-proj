# ADR-015 受控人工身份与原文编号分离

- 状态：已接受
- 记录日期：2026-10-12
- 决定依据：用户明确同意四对象受控登记、原文code空值、未知类型null、不跨报告自动合并及m 2排版等价归一；明确批准最多2次新增64k抽取
- 适用范围：schema_version=0.2.0-draft的受控登记及真实验收；旧0.1.0-draft正常规则保留
- 替代关系：无；补充ADR-002/003/014，不替代旧实验决定

## 背景

真实报告缺少现程序所要求的桥梁/构件明确编号，旧校验器只验证过编号样本。不能为通过填写虚构纸面code，不能按名称自动跨报告合并；原文已有的m2因排版呈现m 2不应改变面积量纲。

## 决定与理由

可信操作员确认的登记表固定当前文档哈希、桥/构件内部ID、名称来源、父关系及可核验源窗口，配置摘要固定并限制在DATA_ROOT内。技术ID与原始bridge_code/component_code分开，原文缺失保持null。v0.2必须有同文档受控登记；v0.1默认代码身份及旧记录不放宽。以父构件登记/原文位置与类型生成document_local病害键，日期或未知状态参与观测键，重复提及不得生成新记录。

关系需登记父对象及实际引用支撑；观测的每个字段来源须在所属源窗口，防止同表其他数值串入。无明确原文构件的negative陈述仅在已登记原文范围支持关联，否则保持问题而不猜。类型错误拒绝，不用登记覆盖模型输出为null。单纯名单、status文字或模型引用都不等于专业终审。

单位仅接受既有m²/㎡/m2的排版空格等价，原始写法不变，Decimal归一；长度/强度、其他单位或未知仍拒绝/待处理。登记不保存预期测量或问答答案，不发送golden；来源窗口引用的是允许发送的真实原文。

## 影响与边界

新增受控格式0.2.0-draft及语义1.2，保留旧格式兼容；代码/Schema允许空编号不等于无条件接纳。登记者确认身份，不代替数据字段/关系/位置的校验和专业系统验收。当前固定四对象的源窗口是首轮核查范围，其余全文仍保存并说明未登记/不支持，不称全文业务已完整抽取；不把不同报告同名对象自动归并。真实多次检测证据仍未获得。

## 规范与验证入口

[主契约新增受控规则](../../specs/001-business-extraction/contract.md#9-受控人工登记语义12)、[实施计划](../../specs/009-controlled-registration/plan.md)、[任务](../../specs/009-controlled-registration/tasks.md)、[根spec §7](../../spec.md#7-业务数据契约)。原运行/首次失败保持，实测结果再回填S5.2，不由已接受ADR推断已完成。

仅对0.2已登记的完整“经检查，桥头平顺，未见明显病害。”范围（允许明确前缀/原句标点），在description/kind/component_ref均引用同一连续原句且合法绑定构件时，程序可从该句派生正式statement.location_text=桥头，并追加程序来源和审计issue。原模型candidate的null不改；不完整句、冲突位置、窗口外或无登记仍拒绝，正式记录再校验。此为既有UT-14位置派生的受控实现，不新增专业推断；原拒绝保留，新无网络验证运行独立记录。
