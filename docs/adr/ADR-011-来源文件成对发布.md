# ADR-011 来源文件成对发布

- 状态：已接受
- 记录日期：2026-10-11
- 决定依据：用户授权修复独立审查confirmed缺陷；既有原子保存/失败可重试要求下的存储实施细化
- 适用范围：LocalFileStore新来源保存，HTTP/本地CLI共享；不改变图登记或解析发布
- 替代关系：无；补充ADR-004

## 背景

逐文件原子保存仍会在PDF成功、source.json失败后留下最终目录，后续同哈希提交被完整性检查拒绝。不能通过覆盖现有目录来修复，否则无法区分崩溃、元信息删除与已有发布损坏。

## 决定与理由

在documents同文件系统的随机临时目录写齐两文件、同步文件及目录后，一次rename发布最终doc目录，再同步父目录。处理到的失败清理本次staging；进程被杀可能留下staging，同hash重传使用新staging。读取与图登记只承认最终完整来源，不读取staging；不自动删除历史或其他进程残留。

已有最终目录仍核对全部元信息/hash/context，不缺文件补猜、不覆盖。旧半写入最终目录无法自动辨认，仍显式错误，需后续受控人工恢复方案；本轮不操作旧DATA_ROOT。首版只支持本机单写者，不引入跨进程CLI共写保障。

## 影响与边界

防止新上传的成对发布窗口阻断同hash重传，保留篡改拒绝及文件/图跨资源边界。staging可能占额外空间；不宣称经过断电或所有文件系统的持久性验证。

[spec §8](../../spec.md#8-文件布局与原子保存)、[修复计划](../reviews/pre-s51-20261011-01/fixes/plan.md)、[来源测试](../../tests/unit/test_file_store.py)。独立故障预期先固定；实际结果另记修复目录。
