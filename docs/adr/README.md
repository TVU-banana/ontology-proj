## 每轮如何维护

1. 开始：读取用户指令与交接，按任务定位相关 ADR；需要了解取舍时才展开正文。
2. 执行：按已授权范围工作；尚未确认的重大选择记录为“待确认”，不据此实施。既有技术默认可按授权范围采用，不冒充用户逐项批准。
3. 检查：每轮改动检查范围、业务语义、架构边界、存储、关键技术选择或验收标准是否产生、改变或推翻决策。新验证结果若动摇选择理由，也需检查。
4. 更新：有新决定则新增记录；实质改变已接受决定则新增替代记录，旧记录标记“已替代”并互链，同步索引与 PRD/spec/contract 等主要维护位置。普通修复、运行结果与任务进度进入 tasks/交接，不逐轮强制改 ADR 正文。
5. 收尾：交接注明“ADR 检查：新增/替代 ADR-xxx”或“ADR 检查：无决策变化”，附相关指针；未解决事项明确保留。只读讨论不强制写文件，用户的讨论/确认边界优先。

## 状态与变更

- 状态固定为：待确认、已接受、已替代、已撤回。索引与正文保持一致；被替代记录不删除，索引保留其状态及后继链接。
- 已接受记录可修正错字、失效链接或补充依据；若改变选择、理由成立条件或约束，则创建新编号，不覆盖历史决定。
- 编号递增且不复用。每份只讨论一个决定，文字尽量短；不复制完整字段规范、任务历史或测试输出。
- PRD/spec/contract 是要求与契约的主要维护位置，ADR 解释取舍；两者冲突时核查来源并同步修正。用户最新明确指令优先，无法确定时询问，不凭旧 ADR 扩大授权。
- 历史补录注明记录日期和来源；无法确认原决定日期时不编造日期。依据性质区分用户确认、既有设计/实施默认和待确认提议。
- 实现与验证引用任务/结果，不用 ADR 状态表达运行能力。结果文件不覆盖首次失败；ADR 不存凭据。

## 新记录格式

复制以下格式，填写真实内容，不为未发生的决定预建空文件：

```markdown
# ADR-NNN 决策标题

- 状态：待确认 / 已接受 / 已替代 / 已撤回
- 记录日期：YYYY-MM-DD
- 决定依据：用户确认 / 既有设计或实施默认 / 待确认提议；附来源
- 适用范围：本决定约束的任务或模块
- 替代关系：无，或前后继记录链接

## 背景
需要解决的问题与限制。

## 决定与理由
选择、成立条件；必要时说明其他方案为何暂不采用。

## 影响与边界
获得什么、承担什么限制；哪些问题仍未决定。

## 规范与验证入口
链接主要规范、任务和结果；说明记录时的证据边界，不复制进度日志。
```
