# ADR-016 文档图片与来源几何补充

- 状态：已接受
- 记录日期：2026-10-13
- 决定依据：用户采纳图片保留、照片与说明关联、续表关联方案并明确要求补全；[阶段计划](../../specs/010-document-structure/plan.md)。
- 适用范围：本地解析与统一文档结构；非业务身份、照片诊断或OCR策略。
- 替代关系：无；细化ADR-004原文与位置保留，不替代业务规则或原S5.2验收。

## 背景

真实四页摘录的文字和表格存在于Docling结果，但20张照片聚成3区域且caption关联为空。规范化未表示图片。继续仅依据原生分割会丢失独立图片及续行关系。

## 决定与理由

继续以Docling负责文本、表格与原生版面；补用本地PDFium逐次图片出现位置和pypdf已描边线段，不替换Docling原生JSON，不重新开发OCR。使用已锁定依赖并显式声明pypdfium2。ParseOutcome增加可选pdf_layout，规范化采用独立可选structure/document-structure-1扩展；原normalized-0.1文字块/ID/charspan/表数据不改变，旧快照只复用不迁写。

几何关联作为derived、有方法和位置证据的文档关系单独保存；歧义或缺证据为unresolved诊断，不改专业事实、不暗继承未知业务身份。跨页照片要求明确同列框线及页边界；续行限明确数字行标记与相同列框线的窄规则。没有支持规则不自动合并，不写死报告名、页码或图号。

## 影响与边界

应用正常解析会保存图片元信息和关系，现有normalized读取接口返回扩展。旧业务抽取仍以原文字块为证据，新增文档关系不自动发布为业务事实或照片诊断；前端新增图库/业务对象身份泛化不在本轮。OCR保持关闭。旋转、裁切非默认页、嵌套Form图片暂不补几何并显示诊断；没有本地版面时保留原生区域，不能冒称逐图识别通过。旧已发布解析不会自动升级，改变配置的失败重试继续受原固定配置检查。
