# ADR-004 本地解析与正式图登记分阶段

- 状态：已接受
- 记录日期：2026-10-11
- 决定依据：用户在本轮明确确认文件/来源、Docling 迁入及验收方案，包括 S2.1 命令行验收、S2.3 正式 API 与图登记边界
- 适用范围：S2.1 本地保存/解析，S2.3 正式来源及状态登记
- 替代关系：无；细化既有计划的阶段依赖，不替代 ADR-001/002/003 或最终接口契约

## 背景
原计划在 S2.1 保存并登记来源，但 Neo4j 到 S2.3 才接入。若把本地文件当作正式登记，会与图状态权威冲突；提前接图或增加第二数据库则扩大当前步骤。

## 决定与理由
S2.1 通过命令行调用共享应用用例，保存原始 PDF、本地来源草稿、原生/统一解析产物及可核查诊断。草稿不是正式 SourceDocument；manifest 只证明产物完整性，不作为业务状态权威。S2.3 重新核验草稿和产物后接入 Neo4j 正式来源/操作登记、串行 runner 与上传/处理/状态 API。

本步沿用文档哈希身份与原子文件保存；同哈希上下文冲突不覆盖，重复提交不自动重跑。统一文档采用 normalized-0.1，并迁入已验证 Docling 配置；保持原文和位置，不补造表头、观测日期或业务事实。

## 影响与边界
无需第二数据库即可先验证解析。代价是 S2.1 尚无正式录入 API/业务图，命令行成功不能计为 A02 端到端成功；HTTP/Agent 最终仍复用共享用例。S2.2 抽取与稳定性门槛不降低，原结果不改写。Neo4j 始终是正式状态权威。
