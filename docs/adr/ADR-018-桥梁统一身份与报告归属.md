# ADR-018 桥梁统一身份与报告归属

- 状态：已接受；普通表格关系证据限制部分由[ADR-021](ADR-021-普通表格业务行证据闭环.md)补充替代，其余身份规则继续有效。
- 记录日期：2026-10-13
- 决定依据：用户确认每桥稳定内部ID与三条归属路径，并明确修改为桥名+地理位置匹配成功自动关联，无人工确认；授权落地。
- 适用范围：新增catalog模式桥登记、报告归属、抽取与图提交。
- 替代关系：补充[ADR-015](ADR-015-受控人工身份与原文编号分离.md)，其旧文档受控登记仍有效，不迁写旧已发布对象。

## 背景

以原文编号直接作为桥技术身份或全局套用单文档登记，会使缺编号的新报告拒绝、同桥生成多个身份，或不同桥套用相同名单。桥梁身份必须独立于纸面编号与模型local_id。

## 决定与理由

每座新登记桥使用稳定brg_技术ID，官方编号存为带体系的独立属性。上传选择、原文官方编号+体系、唯一规范化桥名+完整地理位置三条路径可确定归属；最后一条按用户指令自动关联，不增加人审。名称/位置规范化只NFKC/空白/大小写，官方code及编号体系保持大小写及内部空格语义，不把相似名称或城市级位置当同桥。real/synthetic分区；多个候选/官方冲突/信息不足停在业务抽取前并保留来源依据。人工选择能解决无可靠匹配或名称位置歧义；显式“已核对原文”确认可接受名称/位置显示差异，保留两套原值与确认依据、不改登记名称，但不能绕过明确的官方冲突；未登记桥由操作员登记后继续。

身份库主位置为DATA_ROOT/bridge-identities/state.json：单文件原子保存桥主记录、文档决定、原文证据/快照摘要和操作审计，线程及OS文件锁保护。此为归属的本地事实源，Neo4j保存技术身份与ABOUT_BRIDGE关系；原PDF/解析和正式来源记录不覆盖。应用写入租约及单root单图约束继续。启动接入旧桥时，必须有本DATA_ROOT的已发布记录/来源证明，沿用原ID；不把另一个root的图节点当已登记桥，不重写旧业务或旧图属性。旧未知位置可从人工选桥后原文明确位置补全并保存来源，旧绑定未知快照仍可读。

新增0.4.0-draft/catalog：程序赋桥技术ID，模型仍只提出原文编号/名称并接受字段与关系核验。已归属文档不得降级旧模式绕过。桥节点只维护统一显示身份；每文档原编号/证据留在正式记录和归属决定。构件技术ID包含document_id，暂不跨报告合并；无编号构件仍待处理。旧受控抽取仅用于其固定document_id，其他新文档不继承其名单/窗口。

## 影响与边界

实现的是桥身份与归属，不是任意PDF模板适配、自动地理解析、同名模糊匹配或既有图数据合并。明确标签行和紧邻表格标签/值可发现身份字段；其余布局缺信息需要用户选择/登记。官方体系未给出时不自动做全局编号匹配；用户明确选择可在目标桥唯一对应编号下补足归属范围。不存在官方编号也可凭唯一桥名/完整位置自动关联。实际模型/Neo4j/PDF新链路结果需单独验证，不用离线替身宣称完成。
